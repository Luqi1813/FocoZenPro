# Plano de Avaliação: Refatoração React - FocoZen Pro

## Contexto

O projeto foi recentemente refatorado de uma arquitetura puramente imperativa/DOM para uma arquitetura híbrida React + Legacy. Este plano avalia o estado atual em 5 dimensões: **Sucesso da Refatoração**, **Estabilidade**, **Modularidade**, **Performance** e **Segurança**.

---

## 1. Sucesso da Refatoração

### Estado Atual
- **React 19.2.0** com **Vite 8.0.3** como bundler
- **Arquitetura em 4 camadas**: core (lógica pura), services (bridges), react (UI), renderer (coordenação)
- **Runtime Contracts**: 6 contratos padronizados via `window.FocoZen*Runtime` (Home, Timer, Stats, Goals, Tasks, Assistant)
- **85 testes automatizados** (core + contracts)
- **React islands**: 2 mounts (`#react-app-root` para AppShell, `#react-assistant-root` para AssistantDock)
- **9 componentes React**: AppShell, HomeReactView, StatsReactView, GoalsReactView, SettingsReactView, TimerReactPanel, TasksReactSidebar, AssistantReactDock

### Avaliação: ✅ Parcialmente bem-sucedida

A refatoração atingiu seus objetivos principais - todos os 6 domínios agora têm interfaces React. Porém, a arquitetura híbrida cria uma dependência forte entre React e o renderer legado.

### Problemas Identificados
1. **Arquitetura híbrida incompleta**: O `index.html` ainda carrega ~24 módulos legacy via `<script>` tags antes do React
2. **Estado global mutável**: `src/renderer/state-and-constants.js` declara ~40 variáveis `let` no escopo de módulo
3. **Sem TypeScript**: Todo o código é `.js`/`.jsx`, sem tipagem estática
4. **Sem linting/formatting**: Nenhuma configuração ESLint ou Prettier

---

## 2. Estabilidade

### Estado Atual
- Runtime contracts usam `Object.freeze()` para imutabilidade das APIs
- Snapshots são clonados via `structuredClone` ou `JSON.parse(JSON.stringify())`
- Componentes React usam `startTransition` para atualizações de estado não urgentes
- Cleanup de listeners em `useEffect` returns

### Avaliação: ⚠️ Moderadamente estável

### Problemas Identificados

| # | Problema | Severidade | Localização |
|---|----------|------------|-------------|
| E1 | `process.env.NODE_ENV` hardcoded como `'production'` no Vite config | Média | `vite.config.mjs:8` |
| E2 | Hot reload via `fs.watchFile` + `webContents.reload()` (recarrega janela inteira) | Média | `main.js:99-106` |
| E3 | Chart.js carregado de `node_modules` no HTML (não existe em produção) | Alta | `index.html:223` |
| E4 | `window.updateSidebarProfile` sobrescrito no AppShell sem verificação de tipo | Baixa | `AppShell.jsx:85-88` |
| E5 | `dangerouslySetInnerHTML` usado para changelog sem sanitização | Alta | `SettingsReactView.jsx:182-184` |
| E6 | Breathing 4-7-8 usa `setInterval`/`setTimeout` sem cleanup adequado em re-renders | Média | `HomeReactView.jsx:244-286` |
| E7 | `initialized.current` em HomeReactView pode causar race condition com async | Baixa | `HomeReactView.jsx:378-387` |
| E8 | Sem CI/CD para rodar testes em push/PR | Média | `.github/workflows/` |

## 3. Modularidade

### Estado Atual
- **core/**: 6 módulos puros (constants, utils, history, goals, timer, assistant) - sem dependências de framework
- **services/**: 5 módulos de integração (storage, audio, pip, updates, task-session)
- **react/**: 9 componentes + 6 contracts
- **renderer/**: ~24 módulos legados

### Avaliação: ✅ Boa estrutura, mas com acoplamento residual

### Problemas Identificados

| # | Problema | Descrição |
|---|----------|-----------|
| M1 | **Acoplamento React → Legacy**: Componentes React chamam `window.FocoZen*Runtime` que dependem de variáveis globais do renderer |
| M2 | **Renderer → Core**: Módulos legacy acessam `timerCore`, `audioService`, etc. via `window.*` injetados em `state-and-constants.js` |
| M3 | **Dependência circular implícita**: `runtime-apis.js` referencia funções do renderer (`renderTasksSidebar`, `saveGoalEntry`, etc.) que por sua vez notificam os runtimes |
| M4 | **Contratos inconsistentes**: Alguns contratos expõem métodos de UI (`openCreateModal`, `renderCategoriesChart`), outros apenas dados |
| M5 | **Componentes React muito grandes**: `HomeReactView.jsx` tem 479 linhas com 7 sub-componentes no mesmo arquivo |
| M6 | **Sem barrel exports**: Cada import é caminho relativo explícito, sem `index.js` de re-exportação |

## 4. Performance

### Estado Atual
- `React.StrictMode` habilitado
- `startTransition` para updates de snapshot
- `useCallback`/`useMemo` usados estrategicamente
- `cssCodeSplit: false` no Vite
- `React.memo` mencionado no changelog para componentes folha

### Avaliação: ⚠️ Adequada, mas com oportunidades de melhoria

### Problemas Identificados

| # | Problema | Impacto |
|---|----------|---------|
| P1 | **Bundle único**: Todo o React em um único arquivo `react-app.js` sem code splitting | Médio |
| P2 | **Sem React.memo verificado**: Changelog menciona, mas código atual não mostra `React.memo` nos componentes | Médio |
| P3 | **Re-renders desnecessários**: `HomeReactView` re-renderiza inteiro quando qualquer parte do snapshot muda | Médio |
| P4 | **Breathing 4-7-8 inline**: Componente pesado montado dentro de HomeReactView, deveria ser lazy | Baixo |
| P5 | **Chart.js não tree-shakeable**: Carregado via `<script>` tag, não via import ES | Médio |
| P6 | **`fs.watchFile` com polling de 500ms**: Ineficiente para desenvolvimento | Baixo |

## 5. Segurança

### Estado Atual
- `contextIsolation: true` no Electron
- `nodeIntegration: false` no Electron
- CSP definido no `index.html` com `default-src 'self'`
- `electron-updater` com logging

### Avaliação: ⚠️ Razoável, mas com vulnerabilidades

### Problemas Identificados

| # | Problema | Severidade | Localização |
|---|----------|------------|-------------|
| S1 | **XSS via dangerouslySetInnerHTML**: Changelog renderizado sem sanitização | 🔴 Alta | `SettingsReactView.jsx:182` |
| S2 | **CSP com `'unsafe-inline'`**: Permite scripts inline, reduzindo proteção XSS | 🟡 Média | `index.html:6` |
| S3 | **Fontes externas sem SRI**: Google Fonts e Font Awesome sem integrity hashes | 🟡 Média | `index.html:9-11` |
| S4 | **localStorage sem criptografia**: Dados do usuário (nome, tarefas, histórico) em texto puro | 🟡 Média | Múltiplos arquivos |
| S5 | **`eval`-like patterns**: `onclick` inline no HTML do wizard modal | 🟡 Média | `index.html:76, 84-89, 93-94, 106-107` |
| S6 | **Electron flags**: `disable-site-isolation-trials` reduz sandboxing | 🟡 Média | `main.js:351` |
| S7 | **Sem validação de input**: Nome de usuário e dados de tarefa sem sanitização antes de storage | 🟡 Média | `SettingsReactView.jsx:68-70` |

## Plano de Ação Priorizado

### Fase 1: Correções Críticas (Imediatas)
1. **S1**: Sanitizar changelog antes de `dangerouslySetInnerHTML` ou usar abordagem segura
2. **E3**: Bundlar Chart.js via import ES ou usar CDN com SRI
3. **E1**: Corrigir `NODE_ENV` no Vite config para usar modo correto
4. **S5**: Remover `onclick` inline do wizard modal, usar event listeners

### Fase 2: Estabilidade e Developer Experience
5. **E2**: Implementar Vite dev server com HMR nativo ao invés de file watching
6. **E8**: Adicionar workflow GitHub Actions para rodar testes em PR
7. Adicionar ESLint + Prettier
8. Adicionar `.gitignore` cleanup (remover duplicata)

### Fase 3: Modularidade e Performance
9. **M5**: Extrair sub-componentes de `HomeReactView.jsx` para arquivos separados
10. **P2**: Verificar e aplicar `React.memo` onde necessário
11. **P1**: Implementar code splitting com `React.lazy` + `Suspense`
12. **M6**: Criar barrel exports (`index.js`) para contracts e components

### Fase 4: Segurança Avançada
13. **S2**: Restringir CSP removendo `'unsafe-inline'` onde possível
14. **S3**: Adicionar SRI hashes para CDNs externas
15. **S6**: Avaliar remoção de `disable-site-isolation-trials`
16. **S7**: Adicionar validação/sanitização de inputs

### Fase 5: Roadmap de Longo Prazo
17. Migrar para TypeScript (incrementalmente)
18. Migrar renderer legado restante para React
19. Adicionar testes de componentes React
20. Implementar estado global com Context/Reducer ao invés de CustomEvents
